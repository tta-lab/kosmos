# DeepSeek Harness MCP integration (Kosmos Web profile)

**Scope.** Research only, against the installed local DeepSeek Harness (DSH) checkout at [`47f943859bef60e4160492346772ded9b24f765a`](https://github.com/tta-lab/deepseek-harness/tree/47f943859bef60e4160492346772ded9b24f765a). No server or configuration was installed or changed.

## Findings

- DSH is an **MCP client**, not an MCP server. Its shipped `@deepseek-ai/dsh-mcp-client` bridge exposes only external servers' **tools** (not MCP resources or prompts) to the model as `mcp__<serverName>__<tool>`; the original raw tool name remains on the `tools/call` wire. It uses the official MCP SDK and supports **stdio** child processes and **Streamable HTTP** (`streamable-http`, including SSE), not the legacy standalone SSE transport. [Bridge README](https://github.com/tta-lab/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/packages/mcp/mcp-client/README.md) · [transport implementation](https://github.com/tta-lab/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/packages/mcp/mcp-client/src/transport.ts)
- Configuration is a Cordis patch-list YAML entry per server. Required common fields are `serverName` (unique, `[A-Za-z0-9_-]{1,32}`) and `transport`. `stdio` requires `command` and accepts `args`, `env`, and `cwd`; `streamable-http` requires `url` and accepts `headers`. Both accept `toolCallTimeoutMs`, `failOnStartupError`, and `reconnect` (`enabled`, `initialDelayMs`, `maxDelayMs`, `maxAttempts`). The checked-in minimal grammar is below. [schema](https://github.com/tta-lab/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/packages/mcp/mcp-client/src/index.ts) · [example](https://github.com/tta-lab/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/examples/mcp-memory/mcp-reference-memory.cordis.yml)

```yaml
- insert:
    - id: mcp-example
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: example
        transport: stdio # or streamable-http
        command: example-mcp
        args: []
        env: {}
        cwd: !!js process.cwd()
        # streamable-http instead uses: url: https://example.invalid/mcp
        # and optional: headers: { Authorization: !!js process.env.MCP_TOKEN }
```

- The packaged CLI already depends on the generic client bridge, but ships **no enabled MCP server**. A patch can be supplied transiently with `dsh web --patch <file>`, kept in `$DSH_HOME/profiles/web/cordis.patch.yml` for the Web profile, or in `$DSH_HOME/cordis.patch.yml` for all profiles. Composition order is bundle layers, profile patch, home patch, then command-line patches; later patches replace an addressed row's entire `config`, rather than deep-merge it. [CLI reference](https://github.com/tta-lab/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/apps/cli/reference/README.md) · [memory-MCP guide](https://github.com/tta-lab/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/examples/mcp-memory/README.md)
- MCP server installation is **separate** from MCP configuration. DSH does not download a server, initialize or supervise an independent HTTP service, or supply vendor credentials. For stdio it starts/stops the configured executable with the plugin; for HTTP the service must already run. `dsh plugin --profile web add …` instead runs pnpm and only activates packages declaring a DSH **bundle** patch; a plain dependency is not activated. Thus it is neither necessary nor sufficient for installing/configuring an MCP server. [MCP guide](https://github.com/tta-lab/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/examples/mcp-memory/README.md) · [bundle documentation](https://github.com/tta-lab/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/docs/user/develop/basic/publish.md)
- This is not a usable remote-Web configuration surface. The Web UI has an inventory and three explicitly contributed configuration cards (shell, agent loop, web search); the MCP bridge contributes no settings namespace or card. More generally, settings RPCs are loopback-only. A browser reached through `dsh.localhost:17480` is non-loopback, even though the DSH process binds `127.0.0.1`, so it cannot use settings/credential writes. [Web plugin settings UI](https://github.com/tta-lab/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/packages/client/ui-settings-plugins/src/client/index.ts) · [settings API contract](https://github.com/tta-lab/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/packages/host/apiproxy/src/api/settings.ts) · [remote-Web test](https://github.com/tta-lab/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/apps/web/tests/remote-welcome.e2e.ts)
- Startup waits for initial connect/discovery. A lost stdio connection is retried with bounded exponential backoff (defaults: 500 ms to 30 s, 10 attempts); exhaustion unregisters its tools and requires an MCP-entry reload or Host restart. Disposal closes stdio children and unregisters tools. The shipped Web bundle disables shared module HMR, but profile boot installs a watch-only HMR instance for `$DSH_HOME/profiles/web/cordis.patch.yml` and `$DSH_HOME/cordis.patch.yml`: editing either user layer hot-swaps an MCP entry without a process restart. An immutable `--patch` overlay is parsed only at startup, so the recommended declarative Kosmos overlay—and any server executable upgrade—requires a deliberate `dsh.service` restart. [lifecycle implementation](https://github.com/tta-lab/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/packages/mcp/mcp-client/src/connection.ts) · [Web bundle](https://github.com/tta-lab/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/packages/bundle/web-app/cordis.patch.yml) · [profile boot](https://github.com/tta-lab/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/apps/cli/src/profile-boot.ts)
- Kosmos currently launches the Web profile at loopback with `DSH_HOME=/home/neil/.local/state/dsh`, trusted gateway authority `dsh.localhost:17480`, a systemd user service restart-on-failure policy, and an agenix-provided DeepSeek credential injected only at process start. [Kosmos deployment](../modules/wsl/deepseek-harness.nix) · [Kosmos boundary rationale](secrets.md#deepseek-harness)

## Recommended Kosmos approach

Keep the remote configuration plane closed. Add a reviewed, non-secret MCP overlay to this repository and pass its immutable deployed path as an early `--patch` argument in `dsh.service`; do **not** rely on the remote Web Settings UI or a writable `$DSH_HOME` patch. Declare/pin a stdio server executable as a Nix package (preferred), or run an independently managed loopback HTTP server when HTTP is required. Treat each stdio command, argument list, environment mapping, and working directory as trusted host configuration: DSH runs that child outside the agent sandbox, so neither the model nor a remote UI should choose it. A dedicated DSH bundle is optional: use one only when it genuinely packages a Cordis patch; it does not replace the server package or its lifecycle. [CLI security note](https://github.com/tta-lab/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/apps/cli/reference/README.md)

For an authenticated MCP server, keep its token in a distinct agenix secret and have the service wrapper read it at startup into a narrowly named environment variable. Reference that variable through `config.env` (stdio) or a `!!js process.env…` header value (HTTP); never put its value in YAML, a plugin bundle, or UI settings. This explicit pass-through is required because DSH deliberately removes credential-shaped and `DSH_*` ambient variables before spawning stdio children. [credential scrubbing](https://github.com/tta-lab/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/packages/mcp/mcp-client/src/transport.ts)

After deployment or any overlay/server change, restart `dsh.service` deliberately and verify tool discovery in a new Web session. Do not expose additional DSH settings or credential APIs through Kepos merely to configure MCP.

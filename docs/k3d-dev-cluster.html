Podman + k3d Dev Cluster

Create the first local Kubernetes cluster named dev on NixOS-WSL. The cluster uses k3d backed by Podman's Docker-compatible socket and keeps local-path storage under the home directory for development Postgres data.

Prerequisites

  • Switch the WSL host with the Kosmos flake.
  • Restart the WSL session after switching so the podman group membership applies.
  • Run these commands inside the NixOS-WSL shell, not Windows PowerShell.
sudo nixos-rebuild switch --flake .#wsl
exit

Start a new WSL shell, then verify the tools and socket:

id
podman info
docker info
k3d version
kubectl version --client
tk --version
If docker info cannot connect, check the Podman socket: systemctl status podman.socket. k3d uses the Docker API and should see Podman through /var/run/docker.sock.

Create The Cluster

The API port matches flick-backend/tanka/environments/local/spec.json, which points Tanka at https://127.0.0.1:26443. The extra port mapping exposes the Postgres NodePort so host-side tools can keep using localhost:30432. 

mkdir -p "$HOME/.local/share/flick-backend/k3s-storage"

k3d cluster create dev \
  --api-port 127.0.0.1:26443 \
  -p "30432:30432@server:0" \
  --volume "$HOME/.local/share/flick-backend/k3s-storage:/var/lib/rancher/k3s/storage@server:0"

Verify Kubernetes

kubectl config use-context k3d-dev
kubectl get nodes
kubectl get storageclass
kubectl get svc postgres-dev-postgres-dev

k3s should provide the local-path storage class. PVC-backed development Postgres data will persist through cluster restarts and is stored below ~/.local/share/flick-backend/k3s-storage.

Deploy Flick Backend Local

cd /home/neil/code/projects/GuionAI/flick-backend/tanka
tk diff environments/local
tk apply environments/local

Check the local Postgres workload and migration job:

kubectl get pods
kubectl get pvc
kubectl get svc postgres-dev-postgres-dev
kubectl logs job/db-init-db-init --tail=100

From the WSL host, the development Postgres endpoint stays at localhost:30432.

Daily Commands

k3d cluster list
k3d cluster stop dev
k3d cluster start dev
kubectl get pods

Avoid k3d cluster delete dev unless you intentionally want to recreate the cluster. The host storage directory is separate, but deleting the cluster also removes Kubernetes objects such as PVCs.
